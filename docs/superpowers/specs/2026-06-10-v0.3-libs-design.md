# H-awk v0.3 libs 設計仕様書 (libs/multipart + libs/crypto)

- **プロジェクト名**: H-awk
- **サブシステム**: `libs/multipart`, `libs/crypto`
- **作成日**: 2026-06-10
- **対象バージョン**: H-awk v0.3
- **ステータス**: 承認済み
- **前提仕様**: [`2026-06-06-libs-zig-ext-design.md`](2026-06-06-libs-zig-ext-design.md), [`2026-06-09-libs-net-design.md`](2026-06-09-libs-net-design.md)

---

## 1. 概要

H-awk v0.3 では、以下の 2 つの Zig 製 gawk extension を追加する。

- **`libs/multipart`**: `multipart/form-data` リクエスト (ファイルアップロード) のバイナリセーフなパース
- **`libs/crypto`**: sha256 / HMAC-SHA256 / Argon2id / ECDSA P-256 の暗号プリミティブ群

いずれも `libs/_common/gawk_ffi.zig` の既存フレームワークに従い、`LIBS_LOADED["multipart"]` / `LIBS_LOADED["crypto"]` フラグで存在検出する。libs 不在時は graceful degrade (multipart はエラーログ + 生 body 保持、crypto は gawk 未定義エラー)。

### データフロー: multipart

```
HTTP POST multipart/form-data
  → core/http.awk: body 受信 (既存)
  → core/request.awk: request_parse()
      Content-Type ヘッダを確認
      "multipart/form-data" 検出 → boundary 抽出
      LIBS_LOADED["multipart"] が 1
        → hawk_multipart_parse(body, boundary, req)  ← Zig
            gawk 配列 req に直接書込:
              req["form:<name>"]          テキストフィールド値
              req["file:<name>"]          ファイル内容 (binary-safe)
              req["file:<name>_filename"] 元ファイル名
              req["file:<name>_type"]     Content-Type
        → app.awk ハンドラで req["file:..."] を参照
      LIBS_LOADED["multipart"] が 0
        → log_error("multipart/form-data received but libs/multipart not loaded")
        → req["body"] に生 body を保持 (部分的な degrade)
```

### データフロー: crypto

```
app.awk → hawk_sha256(data)                    → hex string (64 文字)
app.awk → hawk_hmac_sha256(key, data)          → hex string (64 文字)
app.awk → hawk_argon2id(password, salt)        → "$argon2id$v=19$..." encoded string
app.awk → hawk_argon2id_verify(hash, password) → "1" (ok) / "0" (ng)
app.awk → hawk_ecdsa_sign(privkey_b64, data)   → base64url signature
app.awk → hawk_ecdsa_verify(pub_b64, data, sig)→ "1" (ok) / "0" (ng)
```

## 3. libs/multipart 詳細設計

### 3.1 Zig 実装 (`multipart.zig`)

**責務:**
- `--<boundary>` デリミタでリクエスト body をバイト列として分割 (binary-safe)
- 各 part の `Content-Disposition` ヘッダを解析し `name`, `filename` を取得
- 各 part の `Content-Type` ヘッダを解析し MIME タイプを取得
- テキストフィールド → gawk 配列に `"form:<name>"` キーで書込
- ファイルフィールド → `"file:<name>"` / `"file:<name>_filename"` / `"file:<name>_type"` の 3 キーで書込

**gawk 配列書込:** `gawkapi.h` の `set_array_element` を直接使用。`gawk_ffi.zig` の `ffi.Args` 経由で渡された配列参照に書き込む。

**公開関数 (root.zig):**

```zig
// hawk_multipart_parse(body, boundary, req_array) → "1" (success) / "0" (error)
.{ .name = "hawk_multipart_parse", .impl = &multipartParse, .args = 3 }
```

引数:
- `body`: リクエスト body 文字列
- `boundary`: boundary 文字列 (`Content-Type` ヘッダから抽出済み)
- `req_array`: gawk 配列参照 (req に直接書込)

### 3.2 AWK 統合 (`core/request.awk`)

`request_parse()` 内の body 処理部分に multipart 分岐を追加:

```awk
} else if (index(req["header:content-type"], "multipart/form-data") == 1) {
  if (LIBS_LOADED["multipart"]) {
    boundary = _extract_boundary(req["header:content-type"])
    hawk_multipart_parse(req["body"], boundary, req)
  } else {
    log_error("request: multipart/form-data received but libs/multipart not loaded")
  }
}
```

`_extract_boundary()` は `Content-Type: multipart/form-data; boundary=----WebKitFormBoundary...` から boundary 値を抽出する純 AWK ヘルパ関数。

`parse_request_zig()` も同様に multipart 分岐を追加する。

### 3.3 ユーザー向け API (app.awk)

```awk
POST("/upload", function(req, res) {
  username = req["form:username"]         # テキストフィールド
  content  = req["file:avatar"]           # ファイル内容 (binary-safe)
  filename = req["file:avatar_filename"]  # "photo.jpg"
  mimetype = req["file:avatar_type"]      # "image/jpeg"
  json(res, json_encode({"ok": "1", "filename": filename}))
})
```

### 3.4 サイズ制限

- `HAWK_MAX_BODY_SIZE` 超過は `core/http.awk` で弾く (既存)
- multipart 内個別 part のサイズ上限は v0.3 スコープ外

## 4. libs/crypto 詳細設計

### 4.1 Zig 実装 (`crypto.zig`)

すべて Zig 標準ライブラリ (`std.crypto`) を使用。外部依存なし。

**SHA-256:**
```zig
// hawk_sha256(data) → hex string (64 文字)
std.crypto.hash.sha2.Sha256.hash(data, &digest, .{});
// digest[0..32] を hex エンコード → gawk string
```

**HMAC-SHA256:**
```zig
// hawk_hmac_sha256(key, data) → hex string (64 文字)
std.crypto.auth.hmac.sha2.HmacSha256.create(&mac, data, key);
```

**Argon2id:**
```zig
// hawk_argon2id(password) → "$argon2id$v=19$m=65536,t=2,p=1$<salt_b64>$<hash_b64>"
// salt は strHash が内部で CSPRNG から自動生成する
// パラメータ: m=65536 (64MiB), t=2 iterations, p=1 thread
std.crypto.pwhash.argon2.strHash(password, .{
    .allocator = allocator,
    .params = .{ .m = 65536, .t = 2, .p = 1 },
    .mode = .argon2id,
}, &buf);

// hawk_argon2id_verify(encoded_hash, password) → "1" / "0"
std.crypto.pwhash.argon2.strVerify(encoded_hash, password, .{ .allocator = allocator })
    catch return .{ .string = "0" };
return .{ .string = "1" };
```

**ECDSA P-256 (ES256):**
```zig
// 鍵形式: raw bytes を base64url エンコード
//   秘密鍵: 32 bytes (P-256 scalar)
//   公開鍵: 65 bytes (非圧縮: 0x04 || x || y)
const Ecdsa = std.crypto.sign.ecdsa.EcdsaP256Sha256;

// hawk_ecdsa_sign(privkey_b64, data) → base64url signature
const key_bytes = base64url_decode(privkey_b64);
const secret_key = Ecdsa.SecretKey.fromBytes(key_bytes);
const key_pair = Ecdsa.KeyPair.fromSecretKey(secret_key);
const sig = key_pair.sign(data, null);
return base64url_encode(sig.toBytes());

// hawk_ecdsa_verify(pubkey_b64, data, sig_b64) → "1" / "0"
const pub_bytes = base64url_decode(pubkey_b64);
const pub_key = Ecdsa.PublicKey.fromSec1(pub_bytes);
const sig_bytes = base64url_decode(sig_b64);
const sig = Ecdsa.Signature.fromBytes(sig_bytes);
sig.verify(data, pub_key) catch return .{ .string = "0" };
return .{ .string = "1" };
```

> **注:** PEM 形式 (ASN.1 DER パース) は v0.3 スコープ外。鍵は raw bytes の base64url エンコードで受け渡す。

**公開関数 (root.zig):**
```zig
const _ffi_entry = ffi.makeDlLoad(.{
    .name = "hawk_crypto",
    .functions = &.{
        .{ .name = "hawk_sha256",           .impl = &sha256Fn,          .args = 1 },
        .{ .name = "hawk_hmac_sha256",      .impl = &hmacSha256Fn,      .args = 2 },
        .{ .name = "hawk_argon2id",         .impl = &argon2idFn,        .args = 1 },
        .{ .name = "hawk_argon2id_verify",  .impl = &argon2idVerifyFn,  .args = 2 },
        .{ .name = "hawk_ecdsa_sign",       .impl = &ecdsaSignFn,       .args = 2 },
        .{ .name = "hawk_ecdsa_verify",     .impl = &ecdsaVerifyFn,     .args = 3 },
    },
});
```

### 4.2 ユーザー向け API (app.awk)

```awk
# チェックサム / ETag
digest = hawk_sha256("hello world")
# → "b94d27b9934d3e08a52e52d7da7dabfac484efe04294e576fbc5c6cc8e7c584e"... (実際のsha256値)

# CSRF / セッショントークン署名
token = hawk_hmac_sha256(ENVIRON["SECRET_KEY"], session_id)

# パスワード保存 (salt は Zig 側で CSPRNG 自動生成)
hash = hawk_argon2id(password)   # "$argon2id$v=19$..."
ok   = hawk_argon2id_verify(stored_hash, input_password)  # "1" or "0"

# JWT ES256 (手動組立)
function make_jwt(payload, privkey_b64,    h, p, sig) {
  h   = base64url_encode("{\"alg\":\"ES256\",\"typ\":\"JWT\"}")
  p   = base64url_encode(payload)
  sig = hawk_ecdsa_sign(privkey_b64, h "." p)
  return h "." p "." sig
}
```

### 4.3 libs 不在時の挙動

crypto 関数は gawk 未定義 → 実行時エラーで停止。
`LIBS_LOADED["crypto"]` での事前チェックを推奨:

```awk
BEGIN {
  if (!LIBS_LOADED["crypto"]) {
    log_error("crypto functions require libs/crypto")
    exit 1
  }
}
```

## 5. テスト戦略

### 5.1 Zig ユニットテスト

**`libs/multipart/tests/multipart_test.zig`:**
- テキストフィールドのみの multipart body パース
- ファイル + テキスト混在のパース (`form:name` + `file:photo` + `file:photo_filename` + `file:photo_type`)
- バイナリファイル (PNG ヘッダ含む) の boundary 分割が壊れないこと
- malformed boundary (デリミタなし) → エラー返却 ("0")

**`libs/crypto/tests/crypto_test.zig`:**
- sha256: NIST FIPS 180-4 既知テストベクタ照合
- HMAC-SHA256: RFC 4231 テストベクタ照合
- argon2id: `strHash` → `strVerify` ラウンドトリップ (正パスワードで "1")
- argon2id: 誤パスワードで `strVerify` → "0"
- ECDSA: 鍵生成 → sign → verify ラウンドトリップ (正データで "1")
- ECDSA: 改竄データで verify → "0"

## 6. build.zig パターン

libs/net / libs/binary の `build.zig` と同じパターンに従う。

**libs/multipart/build.zig の主要点:**
- `gawk_include` 自動検出 (既存 `findGawkInclude` パターン)
- `ffi_mod`: `gawk_ffi.zig` をモジュールとして追加
- `root_mod`: `root.zig` + `multipart.zig` を import
- `b.addLibrary(.{ .linkage = .dynamic })` で `libhawk_multipart.dylib` / `.so` 生成

**libs/crypto/build.zig の主要点:**
- 同上
- `b.addLibrary(...)` で `libhawk_crypto.dylib` / `.so` 生成
- Argon2id は `std.crypto.pwhash.argon2` → libc allocator 必要 → `.link_libc = true`

## 7. gawk_ffi.zig 拡張

multipart の gawk 配列書込には、`ffi.Args` から gawk 配列参照を取得する API が必要。
現状の `gawk_ffi.zig` が配列書込をサポートしていない場合、以下を追加する:

```zig
// ffi.Args から gawk 配列を取得
pub fn getArray(self: Args, idx: usize) gawkapi.awk_array_t { ... }

// gawk 配列に string キー / string 値をセット
pub fn arraySet(arr: gawkapi.awk_array_t, key: []const u8, val: []const u8) void { ... }
```

これにより `multipartParse` 関数内で `args.getArray(2)` → `arraySet(arr, "file:avatar", content)` のように書込できる。

## 8. 非目標 (v0.3 スコープ外)

- PEM 形式鍵のパース (ASN.1 DER → v0.4 以降)
- multipart 個別 part のサイズ上限
- ファイルのディスク書き出し (一時ファイル保存)
- bcrypt (Argon2id で代替)
- JWT の完全実装 (ヘッダ・ペイロード自動組立)
- libs/gzip, libs/url (v0.4)
